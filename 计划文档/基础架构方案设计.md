# 调试面板插件 (Kotlin 重构版) 基础架构设计方案

## 1. 重构原则与宗旨
* **语言换代**：全面抛弃陈旧的 Java 代码，采用 **Kotlin** 全新编写，利用其简洁、安全的特性。
* **极简侵入**：不强制要求开发者接入特定的技术栈（如 Jetpack Compose）。UI 层坚守 **XML**，保持对各种老旧/现代 Android 项目的完美兼容。
* **零/极少第三方依赖**：为了防止与宿主 App 发生依赖冲突，本插件应尽可能不依赖第三方库（如 Gson, OkHttp），所有核心功能均手写或使用 Android 原生 API 实现。
* **职责单一**：剥离旧项目中过度耦合的复杂业务，回归“提供调试视图”的初心。
* **循序渐进**：**第一阶段只做最基础的代码骨架搭建**，暂不涉及（延后设计）具体业务逻辑如网络日志截取、用户信息数据接口（DataProvider）等。业务功能待骨架夯实后按需逐个设计与集成。

## 2. 模块划分
已在原项目中新建一个全新的 Library Module 来承载重构代码，新旧隔离：
* `logshow-core` (新建)：新的核心模块。包含所有的骨架逻辑、悬浮窗、基础 UI。
* `app` (现有)：作为宿主 Demo 应用，逐步验证新模块的功能。

## 3. 核心架构骨架设计 (第一阶段)

我们采用轻量级的 **门面模式 (Facade)**，目前仅聚焦于入口的把控。

### 3.1 核心入口类：`DebugPanelManager`
* **职责**：整个调试插件的生命周期管理、初始化入口、悬浮窗的显示与隐藏控制。
* **设计**：单例模式。暴露简洁的 `init(application)` 和 `show()`/`hide()` 空壳方法。*（已完成）*

### 3.2 UI 基础骨架设计 (XML驱动) - 即将进行
* **悬浮入口组件 (`FloatingEntranceView`)**
  * 基于 `Activity` 根视图挂载（无需复杂的悬浮窗权限申请）。
  * 负责触摸拖拽、靠边吸附逻辑。
* **调试控制台面板 (`DebugConsoleDialog`)**
  * 采用 `BottomSheetDialog` 或全屏 `Dialog`。
  * 内部使用 `ViewPager2` + `TabLayout`（或简单的自定义 Tab 栏）划分不同的调试模块。
