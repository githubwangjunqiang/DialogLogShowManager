## 1. SDK 核心特性

`ShowLog` 是一套专为 Android 开发者打造的轻量级、高颜值、现代化应用内网络与运行诊断组件库：

- **🚀 零侵入网络拦截**：通过标准 OkHttp 拦截器即可毫秒级无损采集 Request/Response 完整 Headers、Query 参数、JSON/Form 报文体、HTTP 状态码及网络耗时。
- **🛡️ 生产包零开销直通 (Passthrough Mode)**：生产包只需配置 `enabled(false)`，拦截器首行直接放行，不克隆任何 Buffer、不占用 CPU/内存、悬浮球自动隐去、数据库零 I/O 写入，对线上性能与安全性零影响。
- **🛠️ 顶级调试中枢 (ShowLog Hub - 三大同级核心类目)**：
  - **🌐 网络日志**：支持「📋 列表」与「🗂️ 接口分组」瞬切、彩色状态分类 Tab、时间正倒序、日历快捷筛选、智能清理与单条/分组长按删除；
  - **📱 设备系统**：覆盖应用画像、操作系统、硬件屏幕、运行性能等 48 项诊断指标，支持一键导出 Markdown 诊断报告；
  - **🧩 自定义扩展**：SDK 提供承载父布局与当前调试弹框对象，业务方自行填充任意 UI、绑定业务逻辑，并可在适当时机调用 `dialog.dismiss()` 主动关闭调试弹框；
  - **顶级胶囊分段导航**：三者平级并列呈现，支持手势左右平滑滑动（ViewPager2）与点击瞬切，状态互不干扰。
- **⚡ 全局点击防抖**：所有操作入口默认具备 350ms 严格防抖，防止连续误触。

## 2. 快速接入与依赖引入

ShowLog 目前**仅提供 AAR 接入方式**，不提供源码模块依赖（`implementation project(':dialoglogshow')`）。AAR 通过团队私有 Maven 仓库分发，主 SDK 会自动传递依赖底层抓包模块与相关 AndroidX 组件。

### 2.1 配置 Maven 仓库

在工程根目录的 `settings.gradle`（或 `settings.gradle.kts`）中配置团队提供的私有 Maven 仓库：

```groovy
dependencyResolutionManagement {
    repositories {
        // 团队私有 Maven 仓库地址（以实际下发地址为准）
        maven { url 'https://your-maven-repo.example.com/repository/android/' }
        google()
        mavenCentral()
    }
}
```

### 2.2 引入 AAR 依赖

在业务模块（如 `app/build.gradle`）的 `dependencies` 中添加：

```groovy
dependencies {
    // ShowLog 主 SDK（AAR）
    implementation 'com.xq.showlog:showlog:5.0.4'
}
```

> `showlog` 的 POM 会自动解析 `com.xq.showlog:netbare-core:5.0.4`、AndroidX 等传递依赖，无需手动添加。

### 2.3 本地 AAR 离线集成（可选）

若只能拿到本地 AAR 文件，需要同时引入主 SDK 与底层抓包模块，并自行保证 AndroidX、BouncyCastle、Guava 等运行时依赖存在：

```groovy
dependencies {
    implementation files('libs/showlog-5.0.4.aar')
    implementation files('libs/netbare-core-5.0.4.aar')
}
```

> 上述 AAR 文件名以团队实际下发为准。本地 AAR 方式不会自动解析 Maven 传递依赖，且必须保留 AAR 内的 `proguard.txt`（详见第 8 节），否则 Release 包可能出现类被裁剪的问题。优先建议使用 2.2 的仓库依赖方式。

## 3. 初始化配置 (Application)

在宿主 App 的 `Application.onCreate()` 中完成初始化。

推荐配置：**仅在 DEBUG 模式下启用，生产包传入 `false` 零开销熔断**。

```java
package com.your.app;

import android.app.Application;
import com.xq.dialoglogshow.ShowLog;
import com.xq.dialoglogshow.core.config.ShowLogConfig;

public class MyApplication extends Application {

    @Override
    public void onCreate() {
        super.onCreate();

        // 1. 构造 ShowLog 配置
        ShowLogConfig config = new ShowLogConfig.Builder()
                // 生产包开关：生产环境下传入 false，拦截器直接零开销放行，悬浮球自动隐去
                .enabled(BuildConfig.DEBUG)
                // 是否展示屏幕浮窗悬浮球（默认 true）
                .showFloatingView(BuildConfig.DEBUG)
                // 本地 SQLite 最大缓存记录上限（默认 10,000 条，允许范围 100 ~ 50,000 条）
                .maxDatabaseLogLimit(10000)
                // 单条 HTTP 请求/响应报文截断阈值（默认 256 KB，防止大文件 OOM）
                .maxBodyBytes(256 * 1024)
                .build();

        // 2. 初始化 ShowLog
        ShowLog.init(this, config);
    }
}
```

> **提示**：若未传入 `config`，直接调用 `ShowLog.init(this)` 时，SDK 默认启用所有功能，最大日志记录为 10,000 条。

## 4. OkHttp 网络日志自动拦截与业务裁决

### 4.1 基础拦截挂载
在业务中配置你的 `OkHttpClient` 时，只需添加一行拦截器：

```java
import okhttp3.OkHttpClient;
import com.xq.dialoglogshow.ShowLog;

OkHttpClient client = new OkHttpClient.Builder()
        // 挂载 ShowLog 开箱即用的网络拦截器
        .addInterceptor(ShowLog.getOkHttpInterceptor())
        // ... 其他业务配置（超时、Cookie 等）
        .build();
```

#### 生产包零开销机制：
当 `enabled(false)` 时，`ShowLogOkHttpInterceptor` 的首行代码为：
```java
if (!ShowLog.isEnabled()) {
    return chain.proceed(chain.request());
}
```
**不进行任何 OkHttp Buffer 克隆、不打印日志、不解析 JSON，实现与原生 OkHttp 零差别的吞吐性能**。

---

### 4.2 自定义业务成功裁决拦截器 (HttpLogBusinessJudger)

#### 痛点背景：
现代微服务架构中，很多接口即便网络层传输成功（HTTP 状态码为 200），但在业务 JSON 报文中实际返回 `{"code": 401, "msg": "Token已过期"}` 或 `{"code": 50001, "msg": "积分不足"}`，这在业务逻辑上是**绝对的失败**。如果控制台依然显示绿色 200，将严重误导测试与联调人员。

#### 解决方案：
ShowLog 支持配置全局业务裁决拦截器，解耦 HTTP 传输状态与真实业务成败：

```java
// 在 Application.onCreate 中注册全局业务裁决器
ShowLog.setBusinessJudger(context -> {
    // 1. 如果 HTTP 传输层状态码本身非 2xx，直接判定网络失败
    if (context.getHttpCode() < 200 || context.getHttpCode() >= 300) {
        return new HttpLogBusinessJudger.JudgementResult(false, "HTTP " + context.getHttpCode());
    }

    // 2. 便捷解析 Response JSON（SDK 内置安全捕获，非合法 JSON 时返回 null）
    org.json.JSONObject json = context.optResponseBodyAsJson();
    if (json != null) {
        int code = json.optInt("code", 0);
        String msg = json.optString("msg", json.optString("message", "OK"));
        // 约定业务 code != 0 即为失败
        if (code != 0) {
            return new HttpLogBusinessJudger.JudgementResult(false, "业务错误(" + code + "): " + msg);
        }
    }

    // 3. 正常返回业务成功
    return new HttpLogBusinessJudger.JudgementResult(true, "OK");
});
```

- **统一生效标准**：控制台红绿着色、Tab「成功 / 失败/异常」筛选、以及列表副标题**均以业务裁决结果为准**！
- 若未配置该拦截器，默认按 `200 <= httpCode < 300` 判定。

## 5. 非 OkHttp / 自定义网络库上报 (纯抽象契约模式)

对于非 OkHttp 框架（如 Retrofit 底层替换、原生 HttpURLConnection、自研 C++ 网络库、长连接推送等），ShowLog 坚决**反对**让开发者查阅冗长文档去盲猜应该拼装哪些字段。

### 5.1 纯抽象契约设计（无默认实现，IDE 自动补全）
我们定义了纯抽象契约接口 `HttpLogPayload`（**严禁使用任何 default 默认实现**）。开发者只需输入 `new HttpLogPayload()`，按快捷键 `Alt + Enter`（Mac 为 `Option + Enter`），IDE 就会强制自动生成所有 11 个属性方法。开发者无需翻阅任何文档，如同“填空题”般直接填充对应字段：

```java
import com.xq.dialoglogshow.ShowLog;
import com.xq.dialoglogshow.core.model.HttpLogPayload;
import org.json.JSONObject;

// 1. 组装请求与响应的 JSONObject（SDK 内部会自动做 2 空格美化缩进，开发者无需 toString()）
JSONObject requestJson = new JSONObject();
requestJson.put("action", "query_profile");
requestJson.put("userId", 10086);

JSONObject responseJson = new JSONObject();
responseJson.put("code", 0);
responseJson.put("msg", "success");

// 2. 强契约直接上报
ShowLog.report(new HttpLogPayload() {
    @NonNull
    @Override
    public String getUrl() {
        return "https://api.example.com/v1/user/profile";
    }

    @NonNull
    @Override
    public String getMethod() {
        return "POST";
    }

    @Override
    public int getHttpCode() {
        return 200; // 网络传输层状态码
    }

    @NonNull
    @Override
    public String getMessage() {
        return "OK"; // 业务提示信息或失败说明（必填，不可为 null）
    }

    @Override
    public boolean isSuccess() {
        return true; // 核心：本次调用在业务上是否判定为成功（控制台着色与筛选以此为准）
    }

    @Override
    public long getDurationMs() {
        return 168L; // 本次请求完整耗时（毫秒）
    }

    @Nullable
    @Override
    public Map<String, String> getRequestHeaders() {
        Map<String, String> headers = new HashMap<>();
        headers.put("Authorization", "Bearer token_xyz");
        return headers; // 没有可直接返回 null
    }

    @Nullable
    @Override
    public Map<String, String> getResponseHeaders() {
        return null; // 没有可直接返回 null
    }

    @Nullable
    @Override
    public JSONObject getRequestBody() {
        return requestJson; // 强类型 JSONObject，内部自动安全美化排版；无则返回 null
    }

    @Nullable
    @Override
    public JSONObject getResponseBody() {
        return responseJson; // 强类型 JSONObject，内部自动安全美化排版；无则返回 null
    }

    @Nullable
    @Override
    public Throwable getThrowable() {
        return null; // 若发生异常传入 Throwable，内部自动提取并格式化完整堆栈；无则返回 null
    }
});
```

### 5.2 核心设计优势
1. **零摸索成本**：不依赖记忆与文档，编译器与 IDE 强制提示所有必要属性；
2. **强类型支持**：`requestBody` 与 `responseBody` 支持直接传入 `org.json.JSONObject`，杜绝手动拼接字符串的繁琐与潜在转义错误；
3. **成败解耦**：无论 `httpCode` 是 200 还是 500，均通过 `isSuccess()` 与 `getMessage()` 显式声明业务成败与描述，控制台百分百精准呈现。

## 6. 全景调试中枢 (ShowLog Hub) 与三大同级类目

在 ShowLog v5.0+ 中，**「🌐 网络日志」**、**「📱 设备信息」**以及**「🧩 自定义扩展」**作为同等级的三大核心类目并列呈现。

### 6.1 呼出主调试中枢
通过屏幕悬浮球点击，或在代码中调用：
```java
// 唤起全景调试中枢（默认自动定位至上次浏览的类目，或网络日志）
ShowLog.show(activity);

// 精准直达对应大类
ShowLog.showNetworkLogs(activity);    // 直达「网络日志」
ShowLog.showAppDeviceInfo(activity);   // 直达「设备信息」
ShowLog.showCustomPanel(activity);     // 直达「自定义扩展」
```

### 6.2 自定义扩展面板 (Custom Panel)

ShowLog 只提供**承载父布局**与**当前调试弹框对象**，面板内部 UI、数据加载、交互逻辑全部由业务方自行实现。业务方可在父布局中自由 inflate XML 或使用代码构建任意视图，并可在需要时通过 `dialog.dismiss()` 主动关闭调试弹框。

```java
ShowLog.registerCustomPanel("业务环境", new CustomPanelProvider() {
    @Override
    public void onCreateView(@NonNull ViewGroup parent, @NonNull Dialog dialog) {
        // 1. 父布局由 SDK 提供，业务方可自由 inflate 任意 XML
        View content = LayoutInflater.from(parent.getContext())
                .inflate(R.layout.layout_business_debug_panel, parent, false);
        parent.addView(content);

        // 2. 绑定自己的业务逻辑
        TextView tvEnv = content.findViewById(R.id.tv_env);
        tvEnv.setText("当前环境: DEV 测试环境");

        // 3. 在适当时机主动关闭调试弹框
        content.findViewById(R.id.btn_close).setOnClickListener(v -> dialog.dismiss());
    }

    @Override
    public void onDestroyView() {
        // 弹框关闭或面板被重新绑定时回调，释放监听器、定时器、网络请求等资源
    }
});
```

**回调约定：**

| 回调 | 说明 |
| :--- | :--- |
| `onCreateView(parent, dialog)` | 首次进入「🧩 自定义扩展」Tab 时在主线程回调。`parent` 为 SDK 提供的承载父布局，业务方应将自定义视图添加到其中；`dialog` 为当前调试弹框，可调用 `dismiss()` / `cancel()` 关闭。 |
| `onDestroyView()` | 调试弹框关闭或面板被重新绑定时在主线程回调，用于释放业务资源。 |

- 同一弹框生命周期内，同一个 `CustomPanelProvider` 的 `onCreateView` 只会回调一次，切换 Tab 不会重复创建视图，业务面板内部状态不会丢失；
- 每个弹框实例使用创建时已注册的标题和 Provider 快照；若要替换当前面板，请在下一次展示弹框前重新注册，新的配置从下一弹框生效；
- `onCreateView` / `onDestroyView` 均在主线程回调；如需在异步任务中关闭弹框，请切回主线程后再调用 `dialog.dismiss()`；
- 弹框关闭后重新打开，会再次回调 `onCreateView`，业务方应保证面板可以重复创建；
- 面板内容可能超出一屏，请业务方自行使用 `ScrollView`、`RecyclerView` 等可滚动容器；
- 建议在展示调试弹框前完成 `registerCustomPanel` 注册，确保首次进入「自定义扩展」Tab 时即可呈现业务面板；
- 未注册提供者时，SDK 会展示内置接入引导，不影响宿主运行。

> **从旧版迁移**：旧版 `View onCreateView(Context context)` 已移除，请改为 `void onCreateView(ViewGroup parent, Dialog dialog)`，并通过 `parent.addView(...)` 添加原先返回的业务视图。

注册后，主中枢的第三个 Tab 将自动高亮并呈现该面板，与网络日志和设备信息享有完全同等的平级体验。

### 6.3 设备与应用全景看板能力

## 7. 生产包安全与零开销保障

很多团队担心测试监控 SDK 遗留在生产包中引起内存泄漏、性能下降或敏感数据外泄。ShowLog 针对该场景做了多重防护：

| 关注维度 | 调试模式 (`enabled = true`) | 生产直通模式 (`enabled = false`) |
| :--- | :--- | :--- |
| **OkHttp 拦截器** | 完整镜像 Request/Response 抓取 | **首行直接放行，0 内存分配，0 Buffer 克隆** |
| **屏幕悬浮球** | 随 Activity 自动挂载浮窗小球 | **自动卸载并移除，完全不在视图层渲染** |
| **调试中枢 (Hub)** | 点击唤出三大平级暗黑调试面板 | **方法静默熔断，绝不弹窗打扰用户** |
| **SQLite 数据库** | 异步写入本地持久化表 | **写库流程直接 return，0 磁盘 I/O 写入** |
| **内存队列** | 维护最近日志的高速环形缓存 | **零入队操作，内存占用为 0** |

如需在生产包中彻底不包含任何代码，也可以在 Gradle 中通过 `debugImplementation` 隔离依赖。

## 8. 混淆规则 (ProGuard / R8)

**宿主无需手动配置任何 ShowLog 混淆规则。**

ShowLog 仅以 AAR 形式分发，模块内已通过 `consumerProguardFiles "consumer-rules.pro"` 将消费者混淆规则打包进 AAR（AAR 根目录的 `proguard.txt`）。宿主工程开启 R8 / ProGuard 时，Android Gradle Plugin 会自动合并并应用这些规则，业务方无需复制或维护任何 `-keep` 配置。

- 不需要在宿主 `proguard-rules.pro` 中重复添加 `com.xq.dialoglogshow.**` 的保留规则；
- 业务方实现的 `CustomPanelProvider`、自定义面板 View 均通过代码直接注册与调用，不依赖反射，同样不需要额外 `-keep`；
- 本地 AAR 离线集成时，请确保 `proguard.txt` 随 AAR 一起保留；若自行解包、裁剪或二次打包 AAR，删除该文件可能导致 Release 包中弹框、数据模型或自定义扩展回调被 R8 裁剪；
- ShowLog 当前只提供 AAR 接入方式，不提供源码模块集成，因此不存在“源码接入需要自行补混淆规则”的场景。

## 9. API 核心参考速查表

| API 方法 | 作用说明 | 适用场景 |
| :--- | :--- | :--- |
| `ShowLog.init(application, config)` | 初始化 SDK | `Application.onCreate` 中调用 |
| `ShowLog.getOkHttpInterceptor()` | 获取 OkHttp 拦截器单例 | 配置 `OkHttpClient.Builder` 时加入 |
| `ShowLog.setBusinessJudger(judger)` | 注册全局业务成功裁决拦截器 | 解耦 HTTP 状态码与业务 code 成败判定 |
| `ShowLog.report(payload)` | 纯抽象契约模式手动上报日志 | 非 OkHttp / 自定义网络库上报（推荐） |
| `ShowLog.report(record)` | 实体对象模式手动上报日志 | 传统对象化手动构建上报 |
| `ShowLog.show(activity)` | 唤起全景调试中枢 (Hub) | 默认定位到上次浏览类目或网络日志 |
| `ShowLog.showNetworkLogs(activity)` | 唤起中枢并直达「网络日志」面板 | 网络抓包联调 |
| `ShowLog.showAppDeviceInfo(activity)` | 唤起中枢并直达「设备信息」面板 | 排查机型、签名、ABI 与内存瓶颈 |
| `ShowLog.showCustomPanel(activity)` | 唤起中枢并直达「自定义扩展」面板 | 业务自定义调试工具 |
| `ShowLog.registerCustomPanel(title, provider)` | 注入自定义扩展面板；SDK 回调承载父布局与弹框对象 | 接入业务自建调试模块、主动控制弹框关闭 |
| `ShowLog.isEnabled()` | 查询当前 SDK 是否处于启用状态 | 业务层按需获取状态 |
| `ShowLog.setEnabled(boolean)` | 运行时动态切换开关状态 | 灰度配置下发或内部测试设置页面切换 |
